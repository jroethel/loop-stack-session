# Obsidian Board MVP Implementation Plan

> For executors: tasks use checkbox syntax; execute in dependency order; a task is done when its
> acceptance check passes. No specific tooling, harness, or skills are assumed.

**Goal:** one command on Jeremy's Mac renders a board directory inside the Cortex vault where every repo under three scan roots shows as a card in kanban-style columns, flagging any repo with uncommitted or unpushed work.

**Approach:** three pure shell filters wired by a single config-edge script.
`board.sh` discovers repos and emits a Discovery TSV; `board-cards.sh` joins tracker and git signals into a Card TSV; `board-render-obsidian.sh` writes one note per card plus two `.base` views and a health note into the board directory.
A spike settles first whether native Bases renders 8 kanban columns with distinguishable colors or a CSS snippet is needed; everything downstream is a consumer of the TSV, so the surface stays swappable.

**Tech stack:** bash targeting macOS stock `/bin/bash` 3.2 (no associative arrays, no `${var,,}`), git plumbing (no network), `scripts/tracker.sh list` (existing) which emits a JSON array parsed with the repo's existing no-jq brace-scan pattern, Obsidian 1.13.7 with the Bases core plugin, `.base` YAML view files.

**Source brief:** `docs/briefs/2026-09-02.I52.obsidian-board-mvp-brief.md`.

## Global constraints

Host of record for all live verification: Jeremy's Mac, which holds the Cortex vault at `/Users/jjrdar/Documents/_CS_DOCUMENTS_/Obsidian/Cortex`.
Board home: `<CORTEX>/00_System/Board` (the sole output directory).
Scan roots: `~/create`, `~/projects`, `~/repos`; discovery walks each to depth 2, tests each directory for `.git`, follows no symlinks.
Portability: every script targets macOS stock `/bin/bash` 3.2; no associative arrays, no `${var,,}`, no `grep -P`, no GNU-only flags; this matches the constraint `scripts/tracker.sh` already carries.
Git signals use local state only, never the network: `uncommitted` and `ahead` are current; `behind` is shown as-of-last-fetch with its timestamp and never presented as current.
Tracker access goes only through `scripts/tracker.sh list`, which obeys `config/repo-state.md`'s `tracker:` key and emits a JSON array `[{number, title, labels:[{name}], updatedAt}]`; parse it with the no-jq brace-scan pattern already used in `scripts/tracker.sh` (`next-eligible`) and `scripts/gen-mirrors.sh`, so no `jq` dependency is added.
Free-text safety: every free-text field (`title`, `local_position`, `behind_note`, resume-prompt fields) passes through `tr '\t\n' '  '` (tabs and newlines to spaces) before it is written into a TSV row, so a tab or newline in an issue title can never shift or split a row.
No plugin install; Bases core only; a CSS snippet is written only if the spike shows a native shortfall, written once (create-if-absent, never refreshed), and it is the one sanctioned write outside the board directory.
Re-render is atomic and non-destructive: new notes are staged inside the board directory and swapped into place, old card notes are pruned only after their replacements exist, the two `.base` view files are preserved, and nothing else in Cortex is touched; `git status` in every scanned repo is byte-identical before and after.
His-work filter (all roots): a git repo is included when it is conforming OR its `origin` owner matches `LOOP_BOARD_OWNER` (`jroethel`) OR it has uncommitted or unpushed work.
Owner extraction from `git -C <repo> remote get-url origin`, handling both HTTPS and SSH remotes: `sed -E 's#^[a-zA-Z]+://##; s#^[^@/]*@##; s#^[^/:]+[:/]##; s#/.*$##'` (yields `jroethel` from both `https://github.com/jroethel/x.git` and `git@github.com:jroethel/x.git`).
Conformance test: `config/repo-state.md` exists at the repo root.

**Discovery TSV** (tab-separated, one row per discovered git repo, no header, 9 fields in order):

| # | Field               | Meaning                                                                    |
| - | ---                 | ---                                                                        |
| 1 | `repo_path`         | Absolute path to the repo root                                             |
| 2 | `repo_key`          | Path relative to `$HOME`, e.g. `create/loops/loop-stack-session`           |
| 3 | `scan_root`         | Which root it was found under (`~/create`, `~/projects`, `~/repos`)        |
| 4 | `conforming`        | `yes` when `config/repo-state.md` exists, else `no`                        |
| 5 | `included`          | `yes` when the his-work filter admits it, else `no`                        |
| 6 | `last_commit_epoch` | Unix seconds of HEAD commit (`0` if the repo has no commits)               |
| 7 | `uncommitted`       | Count of `git status --porcelain` lines                                    |
| 8 | `ahead`             | Commits ahead of upstream (`-1` when no upstream is configured)            |
| 9 | `behind_fetch`      | `<count>:<fetch_epoch>` behind as of last fetch, or empty when no upstream |

**Card TSV** (tab-separated, one row per card, no header, 12 fields in order):

| #  | Field            | Meaning                                                                     |
| -- | ---              | ---                                                                         |
| 1  | `card_id`        | Stable id: `<repo_key>#<token>` for tracker cards, `<repo_key>#git` for git |
| 2  | `repo_key`       | Owning repo, as in the Discovery TSV                                        |
| 3  | `source`         | `tracker` or `git`                                                          |
| 4  | `column`         | One of the eight columns (below)                                            |
| 5  | `title`          | Card title (issue title, or `<repo_key> working tree` for git cards)        |
| 6  | `token`          | Doc-grammar token: `I<n>` or `B<n>` for tracker cards, empty for git cards  |
| 7  | `staleness_band` | `1`..`4` (below)                                                            |
| 8  | `last_work_date` | `YYYY-MM-DD`: issue `updatedAt` for tracker cards, commit date for git      |
| 9  | `local_position` | e.g. `3 uncommitted, +2 ahead`, or `clean`, or empty for pure tracker cards |
| 10 | `behind_note`    | e.g. `1 behind as of 2026-09-01 14:00`, or empty                            |
| 11 | `health`         | `ok`, `degraded`, or `failed`                                               |
| 12 | `render_epoch`   | Unix seconds of this render (the derived-fact as-of stamp)                  |

**Card-note frontmatter contract** (the single canonical definition; Task 4 emits these keys, the `.base` views in Task 1 read them, each key maps 1:1 from the Card TSV):

```
board_card: true
repo: <repo_key>
source: <tracker|git>
column: <one of the eight>
token: <I<n>|B<n>|empty>
staleness: <1..4>
last_work: <YYYY-MM-DD>
position: <local_position or empty>
behind: <behind_note or empty>
health: <ok|degraded|failed>
render_asof: <ISO-8601 timestamp>
title: <card title>
```

**The eight columns** (kanban order): `backlog`, `next-up`, `in-session`, `blocked-on-you`, `blocked-on-fact`, `awaiting-review`, `handed-off`, `done`.

**Staleness bands** (from `last_work_date` age, and their colors): band 1 `< 5 days` green, band 2 `< 15 days` yellow, band 3 `< 30 days` orange, band 4 `>= 30 days` red.

**Column assignment rules (MVP):**

| Column            | Source rule                                                                    |
| ---               | ---                                                                            |
| `backlog`         | Tracker issue carrying the `idea` label (token `B<n>`)                         |
| `next-up`         | Tracker `agent:todo` / no `agent:` label (token `I<n>`); plus every git card   |
| `in-session`      | Tracker issue with `agent:working`                                             |
| `blocked-on-you`  | Tracker issue with `agent:needs-input`                                         |
| `blocked-on-fact` | Empty column in the MVP (deferred session-card source)                         |
| `awaiting-review` | Tracker issue with `agent:review`                                             |
| `handed-off`      | Empty column in the MVP (deferred session/handoff source)                      |
| `done`            | Empty column in the MVP (see note below)                                       |

Wayfinder-labeled issues (`wayfinder:*`) are excluded entirely (no card).
`done` note: the tracker's only sanctioned path to `agent:done` (`scripts/tracker.sh done`) closes the issue in the same call, and `scripts/tracker.sh list` returns open issues only, so no open `agent:done` issue can exist; the session-card half of the `done` rule is deferred with seam 1.
The MVP therefore renders `done` as an empty column rather than shipping an unreachable rule; populating it (a bounded closed-issue lookback) is a post-MVP pivot.
Three columns (`blocked-on-fact`, `handed-off`, `done`) render empty over real MVP data; all eight still render so the layout is proven, and the Task 1 spike populates all eight with fake cards to verify the kanban shape.

**Git card rule:** the git source emits one standalone card (token empty, `column=next-up`, `card_id=<repo_key>#git`) for every included repo EXCEPT a conforming repo that is clean (zero uncommitted, `ahead` 0 or -1) AND already has at least one tracker card, where the git card adds nothing and is suppressed.
Non-conforming repos, dirty repos, and repos with no tracker cards always get a git card, so every repo appears and every repo with uncommitted or unpushed work is flagged.
Git card `health` is `degraded` when the repo is non-conforming, else `ok`.
The MVP does not merge git and tracker cards: the git-to-tracker token join defers with the tokened git source (session-card docs) in seam 1; criterion 4 (negative join) is satisfied structurally because `card_id` embeds `repo_key`, so issue 52 in two repos yields two distinct ids.

**Health model:** `tracker` source health is `failed` for a repo when its `scripts/tracker.sh list` call exits non-zero (auth, timeout); that repo then contributes exactly one card with `card_id=<repo_key>#tracker`, `health=failed`, `column=next-up`, `title=<repo_key> tracker unavailable`, never zero cards. `git` source health is `ok`; `degraded` is a card attribute (non-conforming repo), not a source failure.

**House style:** plain dash never the em-dash character; one sentence per physical line in prose; aligned pipe tables no wider than 110 characters; plain commit messages with no co-author line.

The full pipeline is one command:

```

```

which internally runs discovery, pipes the Discovery TSV to `scripts/board-cards.sh`, and pipes the Card TSV to `scripts/board-render-obsidian.sh`.

Run the whole test suite with:

```

```

which globs `tests/*/*.sh`; the board suites land in `tests/board/`.
Each board test is self-contained: it builds fixtures under `mktemp -d`, sets the `LOOP_BOARD_*` variables at them, and asserts, so it never touches the real Cortex vault or the real scan roots.

### Task 2: `board.sh` discovery and the config edge

Depends on: none.

**Files (exclusive ownership):**
- Create: `scripts/board.sh`
- Test: `tests/board/discovery.sh`

**Interfaces:**
- Consumes: environment variables `LOOP_BOARD_ROOTS`, `LOOP_BOARD_OWNER`, `LOOP_BOARD_HOME`, `LOOP_BOARD_CORTEX`, `LOOP_BOARD_CSS`. Discovery is git-only and does not call the tracker.
- Produces: `scripts/board.sh discover` prints the Discovery TSV (9 fields, order fixed in Global constraints) to stdout, one row per included git repo, and prints per-root skip counts (`# skipped: N non-git dirs under <root>`) as comment lines to stderr. Bare `scripts/board.sh` runs the full pipeline (`discover | board-cards.sh | board-render-obsidian.sh`, forwarding the skip counts to the renderer via a temp file); this task implements the `discover` subcommand and the pipeline wiring, calling the two downstream scripts once they exist.

Behavior notes:
- Walk each root in `LOOP_BOARD_ROOTS` to depth 2, no symlink following (`find -H` is not used; use `find "$root" -maxdepth 2 -name .git -type d` and take each parent).
- `repo_key` is the repo path with the leading `$HOME/` stripped.
- Included when: conforming (`config/repo-state.md` exists), OR the extracted `origin` owner (Global-constraints sed rule) equals `LOOP_BOARD_OWNER`, OR `uncommitted > 0`, OR `ahead > 0`.
- `last_commit_epoch`: `git -C <repo> log -1 --format=%ct 2>/dev/null` (empty result -> `0`).
- `uncommitted`: `git -C <repo> status --porcelain | grep -c .` (a count, `0` when clean).
- `ahead`/`behind_fetch`: when an upstream exists (`git -C <repo> rev-parse --abbrev-ref --symbolic-full-name @{u}` succeeds), `ahead` = `git -C <repo> rev-list --count @{u}..HEAD` and behind count = `git -C <repo> rev-list --count HEAD..@{u}` with fetch epoch from the mtime of `<repo>/.git/FETCH_HEAD` (`stat -f %m` on macOS, `0` when that file is absent); with no upstream, `ahead` = `-1` and `behind_fetch` empty. No `git fetch` is ever run.
- Non-git directories under a root are counted per root and reported to stderr as `# skipped: N non-git dirs under <root>`.

### Task 3: `board-cards.sh` - Discovery TSV plus tracker into Card TSV

Depends on: Task 2.

**Files (exclusive ownership):**
- Create: `scripts/board-cards.sh`
- Test: `tests/board/cards.sh`

**Interfaces:**
- Consumes: the Discovery TSV on stdin (9 fields, Task 2's contract); tracker issues via a command indirection `TRACKER_CMD` (default `scripts/tracker.sh`) so tests inject a stub. For each conforming, included repo it runs `( cd <repo_path> && "$TRACKER_CMD" list )`, which emits the JSON array `[{number, title, labels:[{name}], updatedAt}]`, parsed with the no-jq brace-scan pattern from `scripts/tracker.sh`.
- Produces: the Card TSV on stdout (12 fields, Global-constraints order); every discovered included repo yields at least one card except a clean conforming repo that already has a tracker card (git-card suppression, see the Git card rule); one tracker card per open non-wayfinder issue in conforming repos.

Behavior notes:
- Tracker JSON parse: extract `number`, `title`, the `labels[].name` set, and `updatedAt` per issue. Free-text fields pass through `tr '\t\n' '  '` before emission.
- Token: `B<number>` when the issue carries the `idea` label, else `I<number>`.
- Column from labels per the Global-constraints table; `idea` -> `backlog`; `wayfinder:*` -> skip the issue entirely; `done`/`blocked-on-fact`/`handed-off` receive no tracker cards in the MVP.
- On a non-zero tracker exit for a conforming repo, emit the single failed card defined in the Health model.
- Git card per the Git card rule: `source=git`, `column=next-up`, `card_id=<repo_key>#git`, token empty, `title=<repo_key> working tree`, `local_position` composed from `uncommitted`/`ahead` (`clean` when uncommitted is 0 and ahead is 0 or -1; when ahead is -1 and uncommitted > 0, show only the uncommitted clause, never `+-1 ahead`), `behind_note` from `behind_fetch` (formatted `"<n> behind as of <YYYY-MM-DD HH:MM>"`), `health=degraded` when non-conforming else `ok`. Suppress the git card for a clean conforming repo that already has at least one tracker card.
- `staleness_band` from `last_work_date` age against the render date: `<5 -> 1`, `<15 -> 2`, `<30 -> 3`, else `4`. Tracker card `last_work_date` = the date of the issue `updatedAt`; git card `last_work_date` = the date of `last_commit_epoch`.
- No git-to-tracker merge in the MVP (deferred to seam 1); `card_id` embeds `repo_key`, guaranteeing the negative join.
- `render_epoch` is one timestamp captured once at start and stamped on every row.
