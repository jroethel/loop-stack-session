# Seam 1: Recording Convention Implementation Plan

> For executors: tasks use checkbox syntax; execute in dependency order; a task is done when its
> acceptance check passes. No specific tooling, harness, or skills are assumed.

**Goal:** every work session in a conforming repo leaves one durable, hand-editable session card, handoff consumption becomes an append-only per-action transition log that auto-archives, and the three empty board lanes populate from those records.

**Approach:** doctrine plus enforcement, not a daemon.
Three small shell scripts write the judgment facts (`session-card.sh`, `handoff-log.sh`) and derive everything else (`take-stock.sh`); `lifecycle-lint.sh` grows a class h behind an adoption-date gate, and `board-cards.sh` reads the derived rows into the empty lanes.
Rollout is piloted on this repo and `~/create/sys-prompts-cc`, proven against the sys-prompts-cc handoff case, then propagated by the template-version roll.

**Tech stack:** bash, awk, plain markdown; no new dependencies.

**Source brief:** `docs/briefs/2026-09-07.I52.seam1-recording-convention-brief.md`

## Plan-owned design calls (decided here, with reversal paths)

**D9, went-stale as card vs flag: flag, carried on a 13th Card TSV field `marker`.**
A went-stale repo has no work item to be a card of, and the shipped renderer has no non-card row concept, so a went-stale card would need a lane it does not have.
The Card TSV grows one field, `marker`, with values empty, `went-stale`, or `died-mid-work`; `went-stale` rides the repo's git card and `died-mid-work` rides the open session card.
A went-stale repo always gets its git card, so the existing clean-conforming suppression rule gains one exception.
Reversal: emit a separate card row with `source=state` and drop field 13, changing `board-cards.sh` and the two board tests only.

**D13, session card key set and `## Log` format.**
Frontmatter, eight keys, each mapping onto a Card TSV field: `session_card`, `session`, `token`, `title`, `status`, `closed`, `why`, `next`.
`## Log` is append-only, one entry per line, `- <ISO-8601 UTC timestamp> <free text>`.
Reversal: add a key to `session-card.sh`'s emitter and to `take-stock.sh`'s reader; existing cards keep parsing because every reader greps line-anchored keys.

**D20, take-stock invocation surface: `scripts/take-stock.sh <repo-root> [--cards]`.**
Single positional argument matching `lifecycle-lint.sh`'s shape; default output is the human recorded-state report, `--cards` emits the 7-field intermediate TSV that `board-cards.sh` consumes.
Reversal: split `--cards` into a second script; the intermediate TSV contract is unchanged either way.

**Went-stale comparison granularity: calendar day, not seconds.**
A commit made seconds after recording is not stale; a repo is went-stale when its newest commit's `YYYY-MM-DD` is strictly later than its recorded-state date.
Reversal: switch to an hour threshold beside `DIED_MID_WORK_HOURS` in `take-stock.sh`.

**Session status to board lane mapping.**
`open` to `in-session`, `blocked` to `blocked-on-fact`, `handed-off` to `handed-off`, `done` to `done`, `aborted` to `done`, `parked` to `backlog`.
`aborted` lands in `done` because it is terminal and not resumable; the card's `why` says it was aborted.
Reversal: one `case` arm in `board-cards.sh`.

**Session card format** (the single canonical definition; Task 1 emits it, Task 3 reads it):

```
---
session_card: true
session: <ISO-8601 UTC, when the card was opened>
token: <I52 | B7 | empty>
title: <one line, what this session is>
status: <open | done | blocked | handed-off | parked | aborted>
closed: <ISO-8601 UTC, empty while open>
why: <one line, the reason for the terminal status, empty while open>
next: <one line, the next action>
---

# <title>

## Log

- <ISO-8601 UTC> opened
- <ISO-8601 UTC> <free text, one line per meaningful step>
```

Path: `docs/sessions/<YYYY-MM-DD>.<tokens>.<slug>.md`, slug from the title lowercased with every run of non-alphanumerics collapsed to a dash; on collision the slug takes a `-2` suffix, then `-3`, and so on.
`log` and `close` target the newest card whose `status:` is `open`, resolved by the `session:` timestamp; with no open card both exit non-zero (exit 3), and with two open cards tied to the second they exit non-zero (exit 7) naming the tied files, because a silent pick between same-second cards would target one at random (the doctrine is one card per session, so a tie is already an anomaly worth surfacing).

**Handoff transition log** (the single canonical definition; Task 2 writes it, Task 2 and Task 3 read it):

```
## Transitions

- <ISO-8601 UTC> action <n> <executed|superseded> - <one-line note>
```

Appended to the handoff file itself, append-only, never rewritten.
The actions section is any `## ` heading whose text starts with `Next actions` (prefix match, so `## Next actions, in recommended order` counts); enumerable actions are the lines beginning `- ` or `<n>. ` inside it, numbered 1..N by position.
This matches the real corpus: the three sys-prompts-cc handoffs all carry numbered `1.` items under prefix-variant headings.
Derived state: `live` when the section is absent, when it parses to zero actions with no bulk line, or when any parsed action has no disposition line; `consumed` when every parsed action has one (or a bulk `action 0` line stands in for a zero-action file) and the file sits in `docs/archive/`; `consumed-unarchived` in the same condition with the file still in `docs/handoffs/`.
The bulk `action 0` line is the legacy-backfill shape for files whose actions cannot be enumerated; it is written by `handoff-log.sh disposition <handoff> all <d>` on a zero-action file, and on a file with parsed actions the same verb appends one line per action 1..N instead.

**take-stock intermediate TSV** (`take-stock.sh <root> --cards`, tab-separated, no header, 7 fields):

| # | Field           | Meaning                                                             |
| - | ---             | ---                                                                 |
| 1 | `kind`          | `repo`, `session`, or `handoff`                                     |
| 2 | `ref`           | repo-relative path of the card or handoff, empty on the `repo` row  |
| 3 | `status`        | session status, or handoff derived state, empty on the `repo` row   |
| 4 | `token`         | doc-grammar token (`I52`), or empty                                 |
| 5 | `title`         | one-line title, tabs and newlines collapsed to spaces               |
| 6 | `last_activity` | `YYYY-MM-DD` of the newest recorded activity for that row           |
| 7 | `marker`        | `went-stale` (repo row), `died-mid-work` (session row), or empty    |

Exactly one `repo` row is emitted, always first.
One `session` row per file in `docs/sessions/`, one `handoff` row per handoff whose derived state is `live`.

**Interfaces:**
- Consumes: nothing from other tasks. Operates on the current working directory's `docs/sessions/`, creating it when absent.
- Produces: three subcommands, all writing plain markdown in the Global-constraints session card format.
  - `session-card.sh open "<title>" [<token>]` creates a card and prints its repo-relative path on stdout; exit 0.
  - `session-card.sh log "<text>"` appends `- <ISO-8601 UTC> <text>` to the newest open card's `## Log`; exit 0.
  - `session-card.sh close <status> "<why>" "<next>"` sets `status:`, stamps `closed:`, writes `why:` and `next:`, and appends a `closed <status>` log line; exit 0.
- Exit codes: 2 on a usage error, 3 when `log` or `close` finds no open card, 4 when `close` is given a status outside the closed vocabulary, 7 when two open cards tie on `session:` to the second (the message names the tied files).

Behavior notes, each edge named:
- Status vocabulary is the exact five-word list; validation is a `case` statement, not a regex.
- Slug: title lowercased, every run of characters outside `[a-z0-9]` collapsed to a single dash, leading and trailing dashes stripped.
- Collision: if `docs/sessions/<date>.<tokens>.<slug>.md` exists, try `-2`, then `-3`, and so on until a free name is found; an existing card is never overwritten.
- Token argument absent means the `token:` frontmatter value is empty; the filename then carries no token segment.
- Free text in `<title>`, `<why>`, `<next>`, and `<text>` passes through `tr '\t\n' '  '` so no value can break the single-line frontmatter shape or split a log line.
- `log` on a card whose `status:` is not `open` exits 3; a closed card is never appended to.
- Key rewrites use `awk` over the frontmatter block and a `mv` of a temp file, never `sed -i` (BSD and GNU disagree on `-i`), and rewrite each key in place so a key is never duplicated.
- The card is committed with the work it records; the script itself never runs git.

### Task 2: `scripts/handoff-log.sh` and `lifecycle-lint` class h

Depends on: none.

**Files (exclusive ownership):**
- Create: `scripts/handoff-log.sh`
- Modify: `scripts/lifecycle-lint.sh` (header class list at lines 3 to 24; new class h block inserted after the class g block that ends at line 242, before `exit "$found"`)
- Modify: `config/repo-state.md` (add one `lifecycle-lint-since:` line under `filename-grammar-since:` at line 8)
- Test: `tests/sessions/handoff-lifecycle.sh`

**Interfaces:**
- Consumes: a handoff file path as its argument; `config/repo-state.md`'s `lifecycle-lint-since:` key, read by `lifecycle-lint.sh` with its existing `fm()` helper.
- Produces: four subcommands plus one lint class.
  - `handoff-log.sh actions <handoff>` prints one row per action, `<n>\t<action text>\t<disposition or ->`; exit 0, exit 0 with no output when the file has no actions section or it parses to zero actions. The section heading matches by prefix (`## Next actions`), and both `- ` and `<n>. ` items enumerate, per the Global-constraints definition.
  - `handoff-log.sh disposition <handoff> <n> <executed|superseded> [note]` appends a transition line; when that disposition completes the set, it archives the file to `docs/archive/` and prints `moved <src> to <dest>`; exit 0. Paths in the announcement print exactly as given on the command line, never relativized or resolved.
  - `handoff-log.sh disposition <handoff> all <executed|superseded> [note]` is the bulk form: one transition line per action 1..N with the same disposition and note, or the single `action 0` bulk line when the file parses to zero actions; archival and announcement as above; exit 0.
  - `handoff-log.sh consume <handoff>` archives and announces when every parsed action has a disposition; otherwise prints `handoff-log: cannot consume <path>: <n> action(s) have no disposition` on stderr and exits 5. A file parsing to zero actions is also refused (exit 5) - the vacuous case never consumes; only `disposition <handoff> all` handles legacy zero-action files, via the `action 0` bulk line.
  - `handoff-log.sh state <handoff>` prints exactly one of `live`, `consumed`, `consumed-unarchived`; exit 0.
- `lifecycle-lint.sh` gains class h: for each `docs/handoffs/*.md` dated on or after `lifecycle-lint-since:`, a derived state of `consumed-unarchived` emits `LINT h <path>: <why>` and forces exit 1. With the key absent, class h does not run at all.

Behavior notes, each edge named:
- Action enumeration: the lines beginning `- ` or `<n>. ` inside the actions section (heading prefix-matched on `## Next actions`), numbered 1..N by position; the section ends at the next `## ` heading or end of file.
- A handoff with no actions section, or one parsing to zero actions and carrying no bulk line, derives `live`; `disposition <handoff> all <d>` is the only path that consumes a zero-action file, via the `action 0` bulk line.
- Disposition vocabulary is the exact two-word list, validated by a `case` statement; anything else exits 4.
- `<n>` outside 1..N (and not the literal `all`) exits 4.
- Re-dispositioning an action appends another line rather than editing the earlier one; the latest line for an action wins when state is derived, and the log is never rewritten.

## Session records

Every work session in a conforming repo opens a session card before its first substantive action and closes it before it ends.
`scripts/session-card.sh open "<title>" [<token>]` at the start, `scripts/session-card.sh log "<one line>"` after each meaningful step - at minimum once per commit, so the card's floor is the commit history's grain - and `scripts/session-card.sh close <status> "<why>" "<next>"` at the end.
Cards live in `docs/sessions/`, one per session, updated in place, and are committed with the work they record.
The terminal status vocabulary is closed: `done`, `blocked`, `handed-off`, `parked`, `aborted`.
A card opened and never closed is, by construction, a session that died mid-work; nothing is recorded at the moment of death.
The recording tax is capped at that one card: everything derivable comes from `scripts/take-stock.sh`, never from hand-recording.
Cards are plain markdown and harness-agnostic - no field names or assumes a particular agent harness, so any harness or a human can write and read them.
`docs/sessions/` is outside the filename-grammar lanes, so lint class f never scans it and the `-2` collision suffix is legal there.

## Handoff lifecycle

Every handoff carries a `## Next actions` section, one action per `- ` line; that list is the enumeration dispositions index into.
Consumption is per action: `scripts/handoff-log.sh disposition <handoff> <n> <executed|superseded> [note]` appends one line to the handoff's own `## Transitions` section.
The log is append-only and current state is always derived from it, never held in a mutable status field; "was this action already done" is answered from history.
`scripts/handoff-log.sh consume <handoff>` refuses while any action lacks a disposition, and the disposition that completes the set archives the handoff automatically, announced under archive rule 5.
`docs/handoffs/` therefore holds only live handoffs.
`scripts/lifecycle-lint.sh` class h enforces this for handoffs dated on or after the `lifecycle-lint-since:` key in `config/repo-state.md`; with the key absent the class does not run, and handoffs dated earlier are grandfathered.
