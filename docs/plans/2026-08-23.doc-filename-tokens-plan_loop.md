## 3. Orchestration shape and validation layers

Three validation layers guard every ringer unit:

1. Implementer self-check: each worker runs the task's `How to run` suite in its own worktree before returning (test-first; specs embed the exact commands).
2. Per-unit validator: the manifest `check` is the primary, non-negotiable gate.
   It executes inside the worktree, prints WHY on failure, verifies substance, and exports the worker's uncommitted diff to `<workdir>/patches/<key>.patch`.
   For the three units that edit or create their own test file (T2, T5, T6) the check is custody-hardened: it greps the worker's test file for the plan's verbatim assertion and fixture lines, never executes a worker-owned script (T6's check byte-diffs the test against a spec-embedded copy and runs that copy), and leaves the owned-suite execution to the gate's full-suite run on the integration branch.
3. Orchestrator gate: this session reads the run JSON and raw logs, applies the reviewed patches to the integration branch, runs the full suite there, and advances only on green.

## 4. Hazard mitigations

- Check custody (deviation from a naive suite-run check).
  T2, T5, and T6 own their own test files, so a check that runs the worker's suite is gameable and ringer's lint rejects it.
  Each of those checks greps the worker's test file for the plan's verbatim assertion and fixture strings; T6's check additionally byte-diffs the test against a spec-embedded copy and executes that copy.
  The owned suites are independently executed at the orchestrator gate (`bash tests/run.sh` on the integration branch), which is outside every worker's reach.
- Within-wave file disjointness (source-plan invariant, preserved).
  Every wave's units own disjoint files (the source plan's `Files (exclusive ownership)` blocks are copied verbatim into each spec).
  A cross-task edit collision at the gate is a scope violation, not something to quietly resolve.
- Worktree isolation and log separation.
  Handled by run-level `"worktrees": true`; not re-specified per task.
- Passing worktrees are deleted and worker commits die with them (ringer footgun, carried).
  Workers leave every change uncommitted; each check ends with `git add -A && git diff --cached > <workdir>/patches/<key>.patch` and fails on an empty patch.
  At the gate the orchestrator applies each patch to the integration branch with `git apply`, commits it with the source plan's per-task message, and spot-checks at least one passing task's deliverables survived the export before advancing.
- Gitignored outputs vanish from patch exports (ringer footgun).
  Not active this run: every deliverable is a tracked source file (config, scripts, skills, tests, ROADMAP.md).
  Stated so the gate does not have to rediscover it.
- OpenCode sqlite-WAL concurrency staggering (ringer footgun).
  Not active this run: the engine is `claude-zai`, not `opencode`.
  Noted for completeness in case a unit is re-routed to opencode at a gate.
- Dirty working tree (source-plan / worktree hazard).
  The two untracked files WAYFINDER.md and docs/memos/loop-setup-virgin.md are RESOLVED: they stay untracked and never enter the run.
  Worktrees branch from committed state only, so untracked files do not travel into any worktree and cannot collide.
  No pre-flight STOP is owed here.
