Method: three fresh-context passes (loop-stack mechanism catalog, mattpocock/skills pattern read, September 2026 native-capability research), deliberately not the loop operating on itself.
This is prep, not a brief; it feeds whatever shaping step Jeremy picks next.

## 2. Target pattern (measured)

mattpocock/skills, local clone at HEAD 84fdeff:

- 35 skills (25 shipped), 6,793 lines of markdown, 104 lines of repo-level plumbing (~65:1).
- Skills are near-pure prose: max 4 frontmatter fields, only 3 of 35 touch a script, dependencies are /skill prose invocations, never file cross-links or absolute paths.
- Two install routes, pick one: the Claude Code plugin (managed, read-only, `claude plugins install`) or `npx skills@latest add` (editable copies).

- Release is changesets plus a 41-line version-sync script; a plugin.json version bump is the entire update story.

## 3. What the harness now does natively (September 2026)

Per claude-code-guide research against current docs; doc URLs in the research output, not independently re-fetched.

- Plugins carry skills, agents, hooks, MCP servers, monitors, and settings; installed via `/plugin marketplace add owner/repo` + `/plugin install`; version-bump updates; works in CLI, desktop, and web (web via settings declaration).
- Long-task orchestration: `/goal` (work until a condition holds, cheap-model evaluator), `/loop` (interval or cron), agent view (`claude agents`: dispatch, watch, attach when input needed), background subagents with completion notifications, SendMessage across sessions, cloud routines that survive session close, script-orchestrated `/workflows`.
- Hooks ship inside plugins; Stop and Notification hooks cover "ping me when a gate needs a human".
- Auto-memory plus the native CLAUDE.md hierarchy covers standing instructions and session-to-session recall.
- Skill frontmatter now includes context: fork, agent:, model:, effort:, allowed-tools, paths - per-skill plumbing the .sh layer used to provide.

## 4. Gap analysis

The distinctive loop-stack IP is prose, and prose ports for free:
the One-Minute Test front door, the brief pipeline, the checkability routing gate, the gate-class taxonomy (ASK/STOP/BATCH/DEFAULT), evidence-over-vibes model routing, the reviewer-conduct contract, the two-axis review, and the wave-compile doctrine in loop-drive.

Nearly all of the 7,901 shell lines exist to provide what is now native or what the target pattern does with prose:

| --------------------------------------------- | ------------------------------------------------------------------- |
| install.sh symlink farm + style knob          | `/plugin install` from own marketplace repo                          |
| Symlinked shared references (contract, bench)  | Single copies in the plugin, reachable via `${CLAUDE_PLUGIN_ROOT}`   |
| tracker.sh 625-line seam + vendoring          | Model runs gh/glab directly per a pointer doc (wayfinder pattern)    |

What has no native replacement and must be ported deliberately: the routing evidence chain (scoreboard posterior -> benchmark prior -> pin), the ringer transport itself (still the answer to the quota constraint), and the evidence-gated done discipline (receipt + re-executed check), which becomes prose convention rather than bash enforcement.

## 5. Dispositions

### Port as-is (prose into plugin skills)

- loop-brainstorm, loop-plan, loop-review, loop-improve, loop-molt: SKILL.md + references, with absolute `~/.claude/...` cross-paths rewritten to /skill invocations or plugin-root paths.
- wayfinder and handoff: already Matt-shaped; wayfinder's tracker-native state model becomes the state model for everything.
- reviewer-conduct-contract.md and model-benchmarks.md: one canonical copy each inside the plugin; the symlink and fail-closed wiring dies.
- Gate-class taxonomy, One-Minute Test, brief pipeline, checkability gate: prose, unchanged.

### Port reworked

- loop-drive: keep the compile doctrine (waves, checkability, routing chain, two transports, human-paced mode); re-plumb execution onto background agents + agent view + notification hooks so Jeremy is involved up-front and pinged at gates, never the baton. Ringer stays a soft optional transport.
- loop-setup: becomes a pointer-doc writer (tracker pointer doc, labels, one CLAUDE.md section), zero vendored scripts; 556 lines of bash -> ~100 lines of prose.
- loop-auto: the knob and gate classes fold into loop-drive prose (or stay a tiny prose-only skill); loop-auto.sh dies.
- loop-track: pure prose; the model files the issue with gh/glab itself; 39-line wrapper dies.
- Tracker semantics worth keeping (agent-label family, evidence-gated done, next-eligible) move from bash into skill prose conventions.

### Left behind

- The board: execute the existing 2026-09-11 extraction brief/plan to jrit-board first; it removes ~1,023 lines and homes #53-55 correctly either way.
- tracker.sh, gen-mirrors.sh + mirrors, migrate-tracker.sh, lifecycle-lint.sh, session-card.sh, handoff-log.sh, take-stock.sh, graduate-parking.sh, tidy.sh, clean-room.sh, and the vendoring/drift-refresh model.

## 6. The one settled decision this contradicts

Today's board-extraction brief keeps the recording convention (session cards, handoff log, take-stock, lifecycle-lint) in loop-stack as the answer to #52, and it shipped to seven repos on 2026-09-08.
The plugin target retires most of it: auto-memory and agent view now cover the resume-pointer problem, and the convention is the largest consumer of vendored bash.
Recommendation: extract the board first exactly as planned (its vendored copies become frozen forks, which the brief already accepts as self-limiting), then retire the recording convention from the canon during the port and let the seven rolled repos keep their frozen copies until each is next touched.
This reversal of a settled decision is Jeremy's call, flagged here rather than taken.
