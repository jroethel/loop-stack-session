# Brief: public distribution of loop-stack (plugin + npx skills, GUI-client reach, bundled ringer)

Supersedes: #32.

## Outcome

loop-stack becomes installable by strangers through the two mainstream channels (the Claude Code plugin marketplace and npx skills), works from GUI non-WSL clients including the Windows 11 desktop app, and ships ringer without requiring a separate manual clone.
Presupposition verdict: "get this ready for marketplace deployment" presupposed the blocker was missing packaging metadata; the 2026-09-10 audit showed the hardcode sweep already passes and the real blockers are repo shape - cross-skill reference reads, repo-root scripts, session history mixed with product, and no packaging, license, or version metadata at all.

## End artifact

A public product repo (working name loop-stack) installable via `/plugin marketplace add` and `npx skills add`, proven by a fresh non-WSL machine driving one real loop end to end.

## Done looks like

- On a clean machine with the Claude Code desktop app: `/plugin marketplace add <owner>/loop-stack` then `/plugin install loop-stack` yields working skills, including loop-drive with its routing reference and reviewer contract present.
- `npx skills add <owner>/loop-stack` installs the skill set, and a single-skill install (`--skill=<name>`) works with no dangling cross-skill reads.
- The bundled ringer verifies against its runtime lock and runs a diagnostic; a host without Python 3.12+ gets an actionable diagnosis, not a silent failure.
- tracker.sh and the other consumer scripts fail with actionable messages when jq, gh, or bash are missing.
- A consumer receives no session history: no sessions, handoffs, reviews, archive, memos, or conversation records.
- This private repo consumes the product repo the same way any other machine does.

## Approach

Chosen: two-repo split in the mattpocock/skills shape - a new public product repo with self-contained skills (shared references duplicated in or converted to Skill-tool invocations), consumer-needed scripts inside the skills that ship them, `.claude-plugin/plugin.json` with a curated skills array plus a fallback `marketplace.json`, LICENSE and synced versioning, a "two ways in, pick one" README, and a vendored ringer bundle (committed dir, runtime lock with pinned upstream revision and per-file hashes, manual reviewed sync/check scripts, ringer root defaulting to the bundle with an external-checkout override).
This private repo stays the dev and session home and consumes the product repo like any other machine.

Considered: in-place publish via a filtered release artifact - one repo with an export script generating the public tree; rejected because the filter becomes a permanent correctness surface (a missed path breaks consumers, an over-included path leaks session history) and every template convention must be enforced through the filter instead of by the repo's own shape.
Considered: skills-only distribution with no plugin packaging - cheapest and the only shape reaching web/cloud, but it abandons the officially supported channel and the desktop `/plugin` flow that this brief exists to reach, while still requiring the same self-containment restructure.

Rationale at decision time: the split resolves the private-history, cross-skill-path, and script-vendoring findings by construction rather than by patching, at the accepted cost of a second repo and a small release habit.

Dated ecosystem facts this rests on (all bought fresh 2026-09-09/10):
- Plugin packaging schema and `${CLAUDE_PLUGIN_ROOT}` path substitution are current Claude Code doc facts; plugins load on CLI and desktop-local sessions.
- Web and desktop-cloud sessions load skills but not plugins or plugin hooks.
- npx skills discovers bare `SKILL.md` paths in a repo tree with no registry file (verified in the mattpocock clone).
- Ringer upstream is PolyForm Shield 1.0.0, Copyright Nate Jones Media LLC (read from the local fork's LICENSE.md); unlock-ai-workbench carries a formal integration authorization beyond the license.

## Success criteria

1. `[executed-check]` The product repo passes Claude Code's plugin validation command at its root (exact command name resolved in planning).
2. `[executed-check]` A staged plugin-layout test (a copy of the product tree with the plugin-root variable set) proves every shipped skill's reference reads resolve inside its own directory, and a grep for `~/.claude/skills/` or repo-root `scripts/` references in shipped skills returns zero hits.
3. `[executed-check]` An npx-skills single-skill install of each shipped skill into a scratch home leaves no dangling reads (a script asserts every referenced file exists).
4. `[executed-check]` The ringer bundle's check script verifies the runtime lock's hashes, and the bundled ringer's own demo/diagnostic exits 0 on a host with Python 3.12+.
5. `[executed-check]` With jq (and separately gh) absent from PATH, tracker.sh exits non-zero with a message naming the missing tool.
6. `[executed-check]` A consumer-content sweep of the product repo finds zero files from the session-history set (sessions, handoffs, reviews, archive, memos, conversation records, learning guide).
7. `[executed-check]` LICENSE exists at the product repo root, the vendored ringer bundle carries the upstream LICENSE.md and Required Notice verbatim, and a drift check fails when plugin.json's version and the package version diverge.
8. `[judgment]` The PolyForm Shield authorization question is resolved with Nate Jones Media and its outcome recorded in the product repo before the marketplace listing goes live; reformulation attempted (a recorded-outcome file check), kept as judgment because the resolution itself is a human negotiation.
9. `[judgment]` One real loop driven from a marketplace install on a non-WSL GUI-client machine lands a unit with tracker receipts; reformulation attempted (the loop's own checks execute), kept as judgment per the 2026-08-16 packaging-brief precedent.

## Seams

1. Skill self-containment restructure - shared references and consumer scripts move inside their owning skills; biggest blast radius because every skill is touched and this private repo's installs must stay green throughout.
2. Product repo extraction - the public repo stands up in the template shape with LICENSE, versioning, plugin and marketplace manifests, and a stranger-first README.
3. Ringer bundle - vendored dir, runtime lock, sync/check scripts, bundle-default ringer root, license notices, and the staged authorization ask.
4. install.sh recast and dependency guards - the consumer path is replaced by the two channels, the maintainer/power-user path is documented, and the jq/bash/git guards land.
5. Proof pass - plugin-layout test, npx single-skill test, and the fresh GUI-client real-loop proof.
