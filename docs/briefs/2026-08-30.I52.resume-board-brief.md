## Outcome

An observability framework over Jeremy's work: one kanban board per host makes the state of every loop-stack project visible - where it paused, what's queued, what's blocked, what's stranded locally, and which projects haven't had a visit in a while.
Each project's work items appear as cards in workflow columns, so the column a card sits in is the record of where things stand.
At the repo level, a session (or Jeremy) asked to resume reads recorded state and names the true frontier instead of reconstructing it from file mtimes and diffing handoffs against reality.
Resuming well is what the visibility enables; it is not an execution feature of the board.

Presupposition verdict: #52 named a per-repo pointer file as the fix.
The real outcome is the observability board; the pointer survives as the per-repo recording layer the board reads, and the "Where I left off" heuristic in `config/conventions.md` (newest handoff vs newest commit) is superseded by it.

## End artifact

The host kanban itself, rendering all conforming repos.
First proof of value: the board resolves the sys-prompts-cc ambiguity (names its authoritative handoff, shows the older one consumed and archived) and flags every repo holding unpushed or uncommitted stopping points - the ones that most need pickup and are invisible to GitHub/GitLab today.

## Done looks like

- One command on the host renders the board: all projects, each project's cards in loop-stack workflow columns, with colors, last-work date, local-vs-remote position (ahead/behind, uncommitted), and what's queued next.
- Cards derive from three sources - GitHub tracker, GitLab tracker, local repo state - and one card can join references across two or all three.
- In any conforming repo, sessions record progress, blockers, milestones, and what's-next as part of working (the handoff skill updates it when used); a take-stock refresh rebuilds a repo's recorded state on demand for the sessions that skipped it.
- Consuming a handoff marks it consumed and archives it; `docs/handoffs/` holds only live handoffs; `lifecycle-lint` gains a class that catches violations.
- The board is read-only and always derived, so it can never go stale or lie; state changes flow through sessions and `tracker.sh`.

## Approach

Chosen: local recording convention + host-derived read-only board.
Each conforming repo records its own state as a side effect of working (session cards for progress, blockers, milestones, what's-next; handoff consumption and archiving), and a host-level board derives cards from the three sources (GitHub, GitLab, local) at render time.
Observability is layered: judgment facts are recorded once where they happen, everything derivable (last-work date, ahead/behind, uncommitted) is computed fresh, and the view holds no state of its own.

Alternatives considered at decision time:

- Derive everything, no recording layer - nothing to maintain, but consumed-vs-live, phase, and effort-shape are exactly the non-derivable judgment facts; observability degrades to inference. Survives as the take-stock refresh engine.
- Hosted board as the home (GitHub Projects v2 or a forked kanban app) - zero render work, but blind to unpushed/uncommitted stopping points, which are the highest-value signals; also account-split and hosting burdens. Parked as a possible future view layer only.

## Success criteria

1. `[executed-check]` One host command renders the board; every conforming repo under the repos root appears, each with its cards or an explicit idle row.
2. `[executed-check]` A repo with uncommitted changes or unpushed commits is flagged; verifiable by making a scratch change and re-rendering.
3. `[executed-check]` A tracker-sourced card reflects tracker state at render time; change a label, re-render, the card moves column.
4. `[executed-check]` At least one card joins a tracker issue and a local artifact and renders as a single card.
5. `[executed-check]` Consuming a handoff marks and archives it; a new `lifecycle-lint` class exits non-zero on a consumed-unarchived or contradicted handoff.
6. `[executed-check]` sys-prompts-cc acceptance: after adoption, its recorded state names the authoritative handoff and the older one is consumed and archived.
7. `[judgment]` A glance at the board answers "where did each project leave off, what needs me" without opening any repo. (Reformulation attempted; criteria 1-6 cover the mechanics, the glance-quality call stays human.)

## Seams (blast-radius order)

1. Per-repo recording convention - session cards, handoff consumption + archiving, take-stock refresh, lint class. Everything else reads this.
2. Card derivation - the three sources, cross-source join rules.
3. Board render - columns, colors, last-work date, local-vs-remote position, grouping by project.
4. Propagation - template-version bump, "Where I left off" superseded, roll to conforming repos.
