# Brief: diagnose whether loop-setup import can silently skip its human ask (#28)

Date: 2026-08-29
Tracker item: issue #28

## Outcome

Determine whether loop-setup's import workflow can file a tracker issue without a human genuinely approving it, before building any enforcement.
The named action (a `/dev/tty`-hardened gate) is a hypothesis about a bug that has not been reproduced.
Presupposition tested and not upheld: the 2026-08-23 evidence cannot distinguish a genuine skipped ask from a by-design re-offer, so the deliverable is a verdict backed by a contract read, not a mechanism.
The diagnosis targets the agent import path (prose disclosure in import-triage.md then `tracker.sh create`), not the bash `reconcile_import` fallback - #28's own wording ("gates `tracker.sh create`") names the agent path.

## End artifact

A recorded verdict - "import can / cannot file an issue without a human approving it, and on which path" - that either closes #28 or hands a known vector to a follow-up design.
The real thing this protects: trustworthy import triage, where no tracker issue is filed without a human genuinely approving it.

The harm model differs by path, and the verdict must keep them separate:

- Agent path: the agent presents a batch disclosure table (import-triage.md), then on assent calls `scripts/tracker.sh create` directly, with no env or code backstop between the prose ask and creation. A skipped disclosure files issues. This is the real exposure.
- Bash `reconcile_import` fallback: a per-item `ask` gate whose unattended creation is double-gated (`LOOP_ASSUME_YES` plus `LOOP_IMPORT_REMOTE`), so a skipped or auto-satisfied ask without the second flag files nothing.

## Done looks like

- A contract read is on record showing what stands between an import candidate and a created issue on each path.
- The verdict states, with `file:line` evidence, whether issue creation can occur without a human approving it, and on which path.
- A recommendation follows from the verdict; the three dispositions are listed, not pre-chosen (per "diagnose then decide").
- Optional confirmation command: a fixture-repo run of the bash fallback to show the `LOOP_ASSUME_YES` env-shortcut concretely, e.g. `LOOP_ASSUME_YES=1 bash setup.sh`; this exercises the fallback only, not the agent path, which a script cannot reproduce.

## Approach

- Chosen: contract-and-code read - map the agent import path against the bash fallback, then read what gates issue creation on each. The reported harm is behavioral (an approval that did not happen); on the agent path that approval is prose-enforced, so the question "can creation occur unapproved" is answered by reading the contract and `tracker.sh create`, not by a fixture run.
- Considered: fixture E2E as primary - rejected, because a bash fixture can only exercise the fallback gates and will always either fire or env-shortcut its ask; it cannot reproduce an agent choosing not to present a prose disclosure. Kept only as an optional confirmation of the fallback's env-shortcut. Instrument-and-wait (log the agent's create calls, catch the next live hit) - most faithful to the agent-compliance failure but unbounded, held as fallback if a live signal is wanted.
- Rationale: inspection can prove a path lets creation happen unapproved; it cannot prove the 2026-08-23 incident specifically fired, which no method can, since the session is unrecoverable and the failure is non-deterministic.

## Success criteria

- `[executed-check]` Reading import-triage.md end to end plus `scripts/tracker.sh create` shows whether anything but agent-followed prose stands between the disclosure ask and issue creation on the agent path.
- `[executed-check]` Reading `ask()` and the `--list-candidates` / `reconcile_import` split shows the bash fallback's gate behavior, including the `LOOP_ASSUME_YES` env-shortcut and the `LOOP_IMPORT_REMOTE` creation backstop.
- `[judgment]` The verdict classifies the 2026-08-23 report as genuine-skip, by-design-reoffer, or indeterminate, and names which path it would have used - kept as judgment because the original session is unrecoverable, so classification rests partly on inference.

## Known vs guessed

- Verified this session: agent import files via `tracker.sh create` after a prose-only disclosure step (import-triage.md); `--list-candidates` exits before `reconcile_import` (setup.sh:112); `tracker.sh create` carries no approval gate; the bash `reconcile_import` fallback double-gates unattended creation at setup.sh:406-409; `ask()` returns 0 without printing under `LOOP_ASSUME_YES` (setup.sh:9-14).
- Believed-unchecked: the 2026-08-23 skip, if real, was on the agent path, since that path matches #28's "gates `tracker.sh create`" wording and lacks a code backstop; breaks if the operator actually drove the bash fallback.
- Guessed: whether 2026-08-23 is reproducible at all - the failure is a non-deterministic agent-compliance lapse, not a scripted code path, so a fixture run will never "forget" to ask the way an agent can.

## Parking lot

- The `/dev/tty` hardened create-gate design - correct target is `tracker.sh create` during import (the agent path), per #28's own wording. Under an agent-driven Bash run `/dev/tty` is not openable and fails closed, so such a gate would block agent-driven creation entirely and make import creation human-terminal-only. Deferred pending a confirmed exposure; this is #28's own hard version, so do not graduate a duplicate.
- Cooperative-strengthen alternative (dry-run-by-default plus a reviewable proposed-issues artifact) - the other mechanism fork if we decide to keep import agent-runnable.
