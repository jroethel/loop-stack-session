## Approach

Chosen: candidate B - one note per card plus two `.base` views, in a board directory under Cortex `00_System`.
`board-cards.sh` emits TSV, unchanged from the plan.
`board-render-obsidian.sh` is a second pure TSV filter: it writes one note per card, a health note, and seeds the views.
Frontmatter holds the machine facts (repo, column, staleness band, health, as-of stamps, join tokens).
The note body holds the human layer, with the resume prompt in a fenced code block.
The two `.base` files live committed in the loop-stack repo as templates and are copied into the board directory only when absent.
Rationale for that call: the views stay versioned and restorable, while tweaks Jeremy makes in Obsidian's UI survive re-renders.
Kanban-style columns are a hard MVP need; drag-and-drop is not, and rides #54.
If the spike shows native Bases falls short on columns or colors, the cover is a CSS snippet, not a plugin (Jeremy's decision 2026-09-02).

The card-note-plus-`.base` shape is the current community standard, not an invention.
Enabling ecosystem facts, dated 2026-09-01 (carried from the fable brief): 20 plugins carry the #kanban tag; the actively developed generation (TaskNotes, Base Board, Dispatch) is uniformly note-per-card frontmatter rendered through Bases; the classic single-file plugin (mgmeyers, 2.6M downloads) lost its maintainer in January 2026 and sits in a community archive.

Alternatives at decision time: A (generated markdown mirror) and C (static self-contained HTML).
Both remain pure consumers of the same TSV and can ship later without rework; neither is built now.
The declined and parked candidates in the tech brief (D-G, Projects v2, Asana) are not re-checked: re-verification only matters if B fails, and B is verified on this host.

## Success criteria (MVP)

1. `[executed-check]` One command renders the board; every repo under the scan roots appears - conforming with tracker-joined cards, non-conforming with degraded git cards.
2. `[executed-check]` A repo with uncommitted or unpushed work is flagged, computed with no network; verifiable by a scratch change and re-render.
3. `[executed-check]` A tracker card moves column when its label changes and the board re-renders.
4. `[executed-check]` Negative join: similarly numbered items from different repos render as distinct cards.
5. `[executed-check]` Re-render replaces card notes inside the board directory only, preserves the two view files, and touches nothing else in Cortex; `git status` in every scanned repo is identical before and after.
6. `[executed-check]` With one source broken, that source renders as failed, never as zero cards.
7. `[executed-check]` Each card's resume prompt is present and derives only from recorded and derived state.
8. `[judgment]` The glance test in Obsidian: kanban-style columns, distinguishable colors, "what needs me" answered without opening a repo. (Reformulation attempted; criteria 1-7 cover mechanics, the glance call stays human.)
